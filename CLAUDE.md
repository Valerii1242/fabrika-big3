# FABRIKA BIG3 · fabrika-big3.com — правила для Claude Code

Полный стандарт: FABRIKA_BIG3_SITE_ENGINEERING_STANDARD v2.0 (у Валерия и в Проекте 1 Claude).
Этот файл — не замена стандарта, а его сжатая версия для старта каждой сессии.

## Repository Identity Gate — обязательно перед любым действием
Подтверди: `git rev-parse --show-toplevel` · `git remote get-url origin` (должен быть
`Valerii1242/fabrika-big3`) · `git rev-parse HEAD` · `git status --short`.
Если origin другой — STOP, ничего не делать.

## Один режим — одна сессия
Один MODE (READ_ONLY_DIAGNOSTIC / PATCH_PLAN_ONLY / SMALL_PATCH / VERIFY_ONLY /
COMMIT_PREP / COMMIT / PUSH), один блок правки, один scope файлов. Не объединять
diagnostics+patch, patch+commit, commit+push. Закрытая сессия не продолжается.

## Стек
Один файл `index.html` (~2600+ строк), Jekyll, GitHub Pages, ванильный JS.
RU/EN — атрибуты `data-ru` / `data-en` + JS `setLang`. Блог — `_posts/`.

## Жёсткие правила
- Файлы в `_posts/` — только с датой в имени: `YYYY-MM-DD-slug.md`. Без даты Jekyll
  молча игнорирует файл (404 без ошибки сборки).
- `data-ru`/`data-en` и логика `setLang` — защищённая зона: отдельный SMALL_PATCH +
  отдельный VERIFY_ONLY, не смешивать с другими правками.
- Кейс 01 (Африка) — эталон, не переписывать без отдельного запроса.
- Деплой только через GitHub (Upload → Commit). Netlify — никогда.
- Git: запрещены `git add .` / `-A` / wildcard staging. Только перечисленные файлы
  принятого scope. commit/push — только по отдельному решению Валерия, никогда не
  автоматически следом за patch.
- Плагины/skills/MCP выключены по умолчанию. Разрешён только `frontend-design` на
  этапе UI-правки, отдельной сессией.

## Конфликты между инструкцией задачи и системными hooks
Если внутренний hook (например, блокировка завершения сессии, требующая commit)
противоречит явному запрету на commit/push в текущей задаче — Claude Code не выбирает
самостоятельно, какое правило нарушить. Обнаружив конфликт, он останавливается,
описывает оба противоречащих требования и возвращает управление Валерию без commit
и push. Молчаливое разрешение конфликта в пользу более настойчивого требования
(включая hook) запрещено — тишина здесь считается нарушением, а не нейтральным
выбором.

## Принятая архитектура (CANON, не пересматривать без нового факта)
Первый экран: CAPITAL (M&A/сделки высокой стоимости) и AI SYSTEMS — с равной
визуальной силой, CAPITAL не убирается и не спускается вниз (статусный якорь,
оправдывающий цену AI-инженерии). Мастер-оффер: «Архитектура решений для задач,
где цена ошибки выше цены анализа». ZG 2.0 — отдельный endorsed-контур
(«ZG 2.0 by FABRIKA BIG3»), не третье равное направление.

## Product Completion Gate
Принятое решение по контенту/архитектуре не пересматривается без нового
подтверждённого факта (изменившееся требование, доказанное противоречие, две
неудачные попытки патча). После утверждения плана — следующий шаг по умолчанию:
реализация, а не новое обсуждение.

## Verification Ladder (кратко)
1. Front matter + имя файла с датой + валидность HTML → 2. Рендер изменённого
блока, RU/EN на нём → 3. Страница целиком, оба языка → 4. Навигация/якоря/sitemap
(раз перед commit) → 5. После push — Ctrl+Shift+R на живом сайте.

## Failed Patch Stop Rule
Два неудачных patch-цикла подряд по одной проблеме → остановиться, зафиксировать
diff и гипотезу причины, вернуть Валерию. Не пытаться в третий раз молча.

## Отчёт закрытия — обязателен в конце каждой сессии
Блок · Mode · Model · Status (CLOSED/NOT CLOSED/WAITING FOR ACCEPTANCE) ·
Files changed · Commit (hash/NOT DONE) · Push (SUCCESS/NOT DONE) · Next step
(один следующий разрешённый шаг).
